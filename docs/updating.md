# 開発版の更新手順

Chrome / Edgeでパッケージ化されていない開発版を使う場合は、リポジトリをcloneしたフォルダー自体を拡張機能の読み込み元として指定します。

## 初回のセットアップ

1. `tomoponz/ai-prompt-macro-public`をローカルにcloneし、ブランチは`main`のままにします。
2. ブラウザの拡張機能管理ページを開き、デベロッパーモードを有効にします。
3. **パッケージ化されていない拡張機能を読み込む**（Load unpacked）を選び、`manifest.json`があるリポジトリのルートフォルダーを指定します。

## 更新

更新作業は、未保存の入力や実行中のRunに影響します。[0.4.4の更新手順](releases/0.4.4.md#既存の手動導入版を更新する)もあわせて確認してください。

1. 必要な診断情報、ChatGPTの下書き、APMの未保存の指示・Flowを退避し、対象を確認して全タブのRunを「停止」します。
2. 拡張機能の読み込み元が意図したcloneフォルダーであり、Gitの`origin`が対象リポジトリを指していることを確認します。現在のファイル一式も別の場所に退避・保全します。
3. 作業ツリーがクリーンな`main`ブランチであることを確認し、ルートの`update-ai-prompt-macro.cmd`を実行します。ZIPから展開したフォルダーではこの補助コマンドは使えません。
4. 更新が成功したら、APMのサイドパネルで **開発版の更新** → **拡張を再読み込み** を選びます。
5. 開いているChatGPTのタブもすべて再読み込みします（`Ctrl+R`）。拡張機能だけを再読み込みしても、開いているページ側に古いスクリプトが残る場合があります。
6. 対象タブと接続状態を確認し、必要な未送信分だけを設定します。更新前の実行の自動継続や、送信済み指示の再送は前提にしません。

この更新スクリプトは、意図的にfail-closed（安全を確認できない場合は更新を中止する）設計にしています。

- ローカルリポジトリが`main`ブランチのときだけ更新します。
- コミットされていない変更や、未追跡（untracked）のファイルが作業ツリーにある場合は更新しません。
- 取得には`git pull --ff-only origin main`を使います。
- reset、clean、強制checkout、force pushは行いません。

なお、このスクリプトは`origin`のURLの妥当性や、現在ブラウザに読み込まれている拡張機能との同一性までは検証しません。更新を通すために未コミットの変更を安易に削除せず、手元の作業をどう保全するか先に判断してください。

サイドパネルの再読み込みボタンは、全タブに`running`または`paused`のRunがなく、状態確認の応答も正常な場合だけ動作します。ブラウザの拡張機能管理画面にある再読み込みボタンにはこの安全確認がありません。拡張機能を再読み込みすると、タブ別の編集状態・選択対象・指定時刻の予定は消去されるため、同じ拡張機能IDであっても未保存の入力が残るとは限りません。

開発用の依存関係と試験手順は[開発と試験](development-guide.md)、再読み込みと再起動の扱いの違いは[ユーザーガイド](user-guide.md#再読み込みと再起動)を参照してください。
