# ユーザーガイド

APMの設定、保存、停止時の対応について説明します。最初の基本操作は[はじめて使う](../getting-started/README.md)を参照してください。以下では、開始から終了までの1回の実行とその保存記録を **Run** と呼びます。

## どの画面で何をするか

| 画面 | 用途 |
| --- | --- |
| サイドパネル「実行コントロール」 | 対象タブの選択、状態の確認、開始・一時停止・再開・停止 |
| サイドパネル「単純繰り返し」 | 同じ指示を指定回数送る |
| サイドパネル「手順を指定」 | AIPM Flowの入力・検証・プレビュー・開始 |
| ワークスペース「Flow / ワークフロー編集」 | 詳細編集、入力だけして確認、部分実行、ライブラリ、読み込み・書き出し |
| ワークスペース「実行一覧」 | 保存済みのRunを閲覧する |
| ワークスペース「ヘルプ・AIヘルパー」 | 使い方の確認、AIへ渡すFlow作成ガイドのコピー |
| 「設定」 | 外観、新しく作るタブ別編集内容の既定値 |

実行の開始・一時停止・再開・停止はサイドパネルで行います。ワークスペースの一覧は保存記録の閲覧用であり、現在の接続状態や実行可否を保証するものではありません。

## タブの表示と操作対象

**「操作するChatGPTタブ」** で選んだ **「操作対象」** が実際の送信先です。**「表示中」** は同じウィンドウで現在前面に表示しているタブを示します。別のタブを見たり、ワークスペースの編集対象を変えたりしても、送信先は自動で切り替わりません。

選択欄には手動で付けた表示名、ChatGPTのページタイトルの順で表示されます。タイトルを取得できない場合は「新しいチャット」または「ChatGPTタブ #番号」となります。同名の会話は実際のタブと照合し、必要なら **「詳細」** のタブID・会話IDを確認してください。表示名・識別色・グループは人が見分けるための補助情報であり、送信先の内部判定には使われません。

ページタイトルは画面上の一時表示にだけ使い、Run・送信記録・診断情報・永続ストレージへの保存や、開発者への送信は行いません。

**新しいチャットでは最初の指示を手動送信してから使います。** 入力欄に文字を置いただけの状態では開始できません。会話が作られ、最初の回答生成が終わったことを確認してから、残りの手順・回数を設定してください。手動送信分はAPMが自動で差し引きません。通常の新規チャットとProject内の新規チャットで共通です。

## 単純繰り返し

**「単純繰り返し」** を選び、次の3項目を設定します。

| 項目 | 内容 |
| --- | --- |
| AIへの指示 | ChatGPTへ送る文章。「よく使う指示」からも選べる |
| 繰り返し回数 | 1〜50回 |
| 追加の待機（秒） | 生成完了を確認した後に追加で待つ時間。0〜300秒 |

入力欄からフォーカスを外すと自動保存されます。開始時にも表示中の内容を保存・照合します。対象・指示・予定回数を確認して **「この内容で自動送信を開始（N回）」** を押してください。Nはこれから自動送信する回数です。

## サイドパネルに手順を貼り付ける

1. **「手順を指定」** を開きます。
2. 必要なら **「AIに手順を作ってもらう」** で目的を書き、**「AI用の作成ガイドをコピー」** を押します。AIへの貼り付けと、出力されたFlowのコピーは自分で行います。
3. **「AIが作った手順（AIPM Flow）」** にFlow本文を貼り付けます。複数ある場合は **「実行するFlow」** を選びます。
4. 入力欄の下の送信回数と手順数、**「実行内容の詳細」**、各指示を展開した全文を確認します。対象・実行範囲・順序・待機・確認ポイントもあわせて確かめます。
5. **「この内容で自動送信を開始（N回）」** を一度押します。

通常の利用では、タブIDの転記、ワークスペースへの移動、事前の手動保存は不要です。コピー・貼り付け・検証を行っただけでは送信は始まりません。自動コピーに失敗した場合は **「コピー内容・AIPM Flow仕様を見る」** から全文を手動コピーできます。

### 対応形式・実行範囲

Flow v1.1では `send`、有限の `repeat`、`wait`、`wait until`、`checkpoint` を使えます。**入力だけして確認するDraft構文はありません。** その操作が必要な場合はワークフローエディターで設定します。

前後の説明文やMarkdownの囲みを除いたFlow本文だけを入力してください。エラーが出た場合は行・列と理由を確認して修正します。説明文からの自動抽出やAIによる自動修復は行いません。「形式と上限を確認済み」という表示は、指示内容の正しさや回答品質を保証するものではありません。

新しく貼り付けた本文はFlow全体を実行対象とします。保存済みの部分実行を開いた場合は、その範囲設定を維持します。実行範囲の変更はワークスペースで行い、開始前にプレビューを確認してください。`wait until` の日時は実際の予定に合わせて書き換え、タイムゾーンも明記します。指定時刻が過去になっていないか、開始前にも確認されます。猶予時間を超え、遅れたときの設定が「確認して停止」の場合は開始せず、予定や設定の見直しを案内します。

### 開始前の編集と複数画面

開始時に対象と内容を固定して保存・照合します。保存失敗、編集競合、開始準備中の内容や対象の変更があれば、新しいRunは開始しません。以前保存した別の内容を代わりに実行することもありません。

別画面から同じタブの内容が更新された場合、未保存の変更がなければ新しい保存内容を表示します。未保存の変更がある場合は手元の入力を保持し、保存・開始を止めます。**「自分の入力をコピー」** で退避し、必要なら **「保存済み内容を読み直す」** を使ってください。自動マージや上書きは行いません。

操作対象を切り替える際も、未保存の入力を別タブへ自動で転記しません。画面の案内に従って退避してください。編集中の変更は、すでに動いているRunの内容や送信先には反映されません。なお、この編集競合の案内は、送信結果不明やRunの停止とは別の仕組みです。

## ワークスペースで詳しく編集する

**「ワークスペース」** → **「Flow / ワークフロー編集」** を開きます。**「保存済み編集項目」** で対象を選ぶか、**「正確なタブID」** を入力して **「読み込む」** を押します。タブIDはサイドパネルの **「詳細」** で確認できます。

画面のボタンで手順を組むのが **ワークフローエディター**、テキスト形式で記述するのが **Flowエディター** です。どちらも事前に決めた手順を順番に実行するもので、回答内容による条件分岐は行いません。

### ワークフローエディター

設定した手順を上から順に実行します。**「↑」「↓」** で並べ替え、**「×」** で削除できます。

| 追加ボタン | 設定するもの |
| --- | --- |
| AIへの指示を追加 | 指示、動作、繰り返し回数、完了後の待機 |
| 待機を追加 | 待機時間（秒） |
| 指定時刻まで待つ手順を追加 | PCのローカル日時、遅れたときの対応、許容する遅れ |
| 確認ポイントを追加 | 確認時のメッセージ |

**「入力して送信」と既存の入力**

最初の指示が「入力して送信」の場合、開始時に入力欄にある文章やプラグイン名などを残し、その末尾へAPMの指示を追記して一緒に送ります（特定のプラグイン名一覧で許可を判定する方式ではありません）。構造化された入力も元のノードを保ったまま追記し、保全を確認できない構造や途中の手動操作があれば停止します。

元の入力内容は、最初の送信で入力欄から消えた後の2回目以降の反復には復元されません。一時停止からの再開時にも残った入力を確認し、同じ指示を二重に追記しないよう制御します。ページの再読み込みなどで同一性確認の根拠を失った場合は、入力を保全したまま止まります。送るつもりのない文章は開始前に退避してください。

**長文が添付になった場合**

開始前からある未確認のファイル添付を送信する機能ではありません。入力前に添付がなく、同じ入力操作から単一の認識可能な候補が現れ、対象・入力履歴・送信準備を確認でき、かつ途中の手動操作がない場合に限って送信を進めます。もともとの入力が消えたからといって「全文が添付になった」と推測して送ることもありません。

添付ファイルの全文を読み取って元の指示と照合する仕組みではありません。別のファイルアップロードが遅れて同じ形で現れた場合など、画面上の観測だけでは区別できない限界があります。開始前に進行中のファイル追加や未送信の添付がないことを確認し、実行中は入力欄・添付を操作しないでください。条件を確認できない場合は、添付を勝手に削除せず停止します。**0.4.4の実ChatGPTでの最終動作確認は未実施です。**

**「入力だけして確認」**

空の入力欄へ指示を置き、自動送信せずに **「確認が必要」** の状態で止まります。既存の下書きや添付がある場合は書き換えません。

1. ChatGPTの入力欄を確認し、必要なら手動で編集します。
2. 送信する場合はChatGPT側の送信ボタンを自分で押します。
3. 必要な回答生成が終わり、次の手順へ進めてよいことを確認してから、サイドパネルの **「再開」** を押します。

最終的に何を手動送信したかや、回答内容が適切かをAPMが読んで判定するわけではありません。一方、**確認ポイント** は入力欄へ文字を書かず、指定したメッセージを表示して同じく確認待ちで止まります。

**指定時刻に遅れた場合**

許容する遅れを超えた場合、**「確認して停止」** は確認待ちで止まり、**「遅れても実行」** はそのまま次へ進み、**「遅れたらスキップ」** はその待機手順だけを飛ばして次の手順へ進みます（後続の指示まで削除する意味ではありません）。また、スリープ中のPCや閉じたブラウザを自動で起動する機能はありません。

### Flowエディターと保存

**「Flowテキスト」** に構文を記述し、**「検証 / プレビュー」** で実行するFlowと範囲を選び、予定回数を確認します。部分実行では前の会話の文脈が必要になる場合があるため、対象の会話と実行範囲が合っているかも自分で確認してください。

| 保存操作 | 保存するもの |
| --- | --- |
| 編集状態を保存 | 選んだタブで実行する内容 |
| Flowライブラリの新規保存・上書き保存 | 再利用するFlowテキスト、名前、説明など |
| 現在のFlowを書き出す | 手元のテキストファイル |

読み込みや保存を行っただけでは実行は始まりません。実行したい内容を **「編集状態を保存」** し、サイドパネルで同じ対象タブの **「保存済み実行内容」** とプレビューを確認してから開始します。自動送信を含まない内容では、開始ボタンに **「この内容で開始（自動送信0回）」** と表示されます。

別画面との更新が競合した場合は、手元の入力を保持して保存を止めます。必要な内容を手元へ退避してから **「保存済み内容を読み直す」** を使ってください。

## 状態・接続・進捗の読み方

| 実行状態 | 意味 |
| --- | --- |
| 待機中 | 現在のRunがない。開始には対象と接続の確認が必要 |
| 実行中 | 保存記録では進行中。追加待機・指定時刻待ちも含む |
| 一時停止中 | 利用者が一時停止し、再開可能な状態 |
| 確認が必要 | 人の確認を待っている。理由を読み、再開可能な場合だけ続ける |
| 安全のため停止 | 不確かな状態で自動継続しない。通常の再開はできない |
| 完了 | 予定した手順を終えた。回答品質の判定ではない |
| 停止済み | このRunを終了した |
| 状態不明 | 保存状態を判別できない |

**「接続状態」** はRunの実行状態とは別の表示です。一時的な通信確認の失敗時に直前の表示を保つ場合もあるため、接続状態の表示だけで送信済みか未送信かを判断しないでください。

サイドパネルの送信進捗には、次の手順へ進む前であっても、送信受付が確認された時点で1回分が加算されます。一方、ワークスペースは保存された手順単位の進捗を表示するため、一時的に数値が異なる場合があります。数値の差だけを理由に手動で再送しないでください。

ワークスペースの **「一時停止・確認待ち・安全停止」** は3つの状態をまとめた絞り込みフィルタです。実行一覧は過去の完全な履歴ではなく、現在保存されているタブ別のRunを表示します。

## 止まった理由と次の操作

送信ボタンの操作、送信受付の確認、回答生成完了の確認はそれぞれ別の段階として扱われます。**一度確認された「送信済み」の記録が、その後の状態確認の失敗によって「送信結果不明」へ戻ることはありません。**

| 状況 | 対応 |
| --- | --- |
| 送信結果が不明 | 同じ指示を自動再送しません。ChatGPT側を確認して停止し、必要なら未送信の指示だけを新しく設定します |
| 送信前に停止し、再開可能と表示 | 今回の指示はまだ送信ボタンを押していません。入力欄・送信先・理由を確認して再開します |
| 送信確認済みだが生成完了・次の入力準備が未確認 | 再送しません。「再開」が有効なら、生成完了と入力準備の再確認から続けます。再開できなければ停止します |
| 対象の会話・ページが同じか確認できない | 停止し、正しい対象と送信済みの範囲を確認します。別の会話へ自動で切り替わりません |
| 対象タブへ接続できない | 接続不明は送信失敗や実行終了の証拠ではありません。選んだタブと「次の操作」を確認します |
| CAPTCHA・ログイン・利用上限・サービスエラー | ChatGPT側で正規に対処します。回避はしません。再開可能な表示の場合だけ再開します |
| 送信上限に到達・同じ会話の同時操作が競合 | そのまま追加送信しません。停止し、送信済みの内容と他のRunを確認します |

自動再送しない仕組みは、同じRunの同じ送信位置に対する保護です。利用者が手動で送信することや、新しいRunに送信済みの指示を含めて開始することまでは防ぎません。新しく設定し直す前に、未送信の指示だけが残っていることを必ず確認してください。

ページ側の自動進行が止まっていても、停止要求が現在のRunに対する正当な権限を持つと確認できない場合、保存表示に **「実行中」** が残ることがあります。表示だけで動作中・終了済みを断定せず、必要な診断を保存し、対象と送信済みの範囲を確認して **「停止」** してください。開始・再開・再読み込みの連打で解消しようとしないでください。

### 以前のRunが新しい会話の最初の送信操作後で止まっている場合

旧Runが最初の送信後に **「確認が必要」** で残っている場合の互換手順です。会話のURLが変わっただけでは自動続行しません。

同じタブで、その操作によって作られた会話であり、最初の指示が1回だけ送られたことを確認して **「再開」** を押します。対象を再確認できれば、その指示を送信済みとして数え、再送せずに残りへ進みます。別の会話へ移動した場合や確信が持てない場合は **「停止」** してください。

新規Runは、最初の指示を手動送信した後に開始する運用です。この互換処理は、新規Runの開始前に手動送信した分を自動で差し引く機能ではありません。

### 一時停止・再開・停止

- **「一時停止」**：以降の自動進行を止めます。送信操作のタイミングと重なった場合は、その1回の送信確認まで進んでから止まることがあります。送信結果が不明になった場合は再開不可の安全停止に移行します。
- **「再開」**：一時停止、送信前の再開可能な停止、送信確認済みの生成待ち、確認ポイント、入力だけして確認など、再開が許可された状態でのみ使えます。確認済みの指示は再送しません。
- **「停止」**：APMの今後の自動操作を終えます。ChatGPT自身の回答生成は止めません。生成も止めたい場合はChatGPT側の停止ボタンを操作してください。

ボタンが有効かどうかと **「理由」「次の操作」** の表示を確認してください。再開ボタンの連打で安全停止を解除することはできません。

## 復旧方針と設定

サイドパネルの **「復旧方針」** は、選んだタブの実行内容に適用されます。**「標準」** は通常の確認回数・待機時間、**「完了を優先」** は上限の範囲内で状態確認や準備待ちを長めに行います。完了を保証したり、結果不明の送信を再試行したりする設定ではありません。対象の確認、同時操作の防止、最大50回の上限、回答本文を読まない制約はどちらの方針でも共通です。

**「設定」** にある実行の既定値は、新しく作るタブ別編集内容の初期値として使われます。すでに保存済みの内容や実行中のRunは変更しません。外観の設定は画面表示へ即時に反映されます。診断の **「要約」「詳細」** は技術詳細の欄を最初から開いて表示するかどうかの設定であり、記録される内容や安全条件は変わりません。

## 再読み込みと再起動

| 操作・出来事 | 動作と注意 |
| --- | --- |
| ChatGPTページの再読み込み（Ctrl+R） | 同じブラウザ起動中・同じタブ・同じ会話で、安全を確認できる状態だけ復旧できます。送信確認済みの生成待ちや保存済みの待機は続けられる場合があります |
| 送信途中でページを再読み込み | 送信確認前に中断した通常送信は結果不明として止まり、自動再送しません。旧Runの新しい会話の確認待ちも自動解除しません |
| 拡張を再読み込み・更新 | 以前のRunを自動継続せず、タブ別編集内容・選択対象・指定時刻の予定を消去し、スリープ防止を解除します。必要な内容を先に退避し、全Runを停止してから行います。更新後はChatGPTページも再読み込みします |
| ブラウザ内部でバックグラウンド処理が再生成 | 同じブラウザ起動中なら保存状態と安全条件を再確認します。拡張やブラウザ全体の再起動とは異なり、無条件の継続でもありません |
| ChatGPTタブを閉じる | そのタブのRunを続行不可にし、指定時刻の予定とタブ別編集内容を削除します |
| Chrome / Edgeを完全終了して再起動 | 以前のRunを自動継続しません。タブ別編集内容・選択対象・指定時刻の予定を消去し、スリープ防止も解除します |

サイドパネルの **「拡張を再読み込み」** は、全タブで実行中・一時停止中のRunがないと確認できた場合だけ実行できます。状態確認の失敗や不正な応答がある場合は実行せず、確認中の重複クリックも無視します。なお、ブラウザの拡張機能管理画面からの再読み込みにはこの事前確認は適用されません。

Flowライブラリへ明示的に保存したデータは、タブ別編集内容とは別に保持されます。ただし「保存」は再起動後の自動継続を意味するものではありません。

## スリープ防止

開始前に **「実行中のスリープを防ぐ」** を有効にすると、実行中だけPC本体の自動スリープを抑止するようブラウザへ要求します。ディスプレイの消灯は妨げません。一時停止・停止・完了時にそのRunの要求を解除し、複数の有効なRunがある場合は最後の1つが止まるまで要求を維持します。

すでにスリープ状態のPCを起こす機能ではありません。手動でのスリープ操作、ノートPCの蓋を閉じる操作、OSや組織のポリシー設定を必ず上書きできる保証もありません。PCがスリープ・休止・電源オフになっている間は自動実行は進みません。

## 保存・複数タブ・プライバシー

編集内容とRunはタブ別にブラウザ内へローカル保存します。異なる会話であれば並行して実行できますが、同じ会話を複数のRunで同時操作することは防ぎます。再利用したいFlowはライブラリへ明示保存するか、テキストファイルとして書き出してください。クラウド同期は行いません。

APMは回答本文を取得・保存・解析・書き出しせず、回答内容による条件分岐にも使いません（**Output-Blind**）。入力欄、送信・生成状態の操作部品、制限・確認画面、会話識別に必要なURL情報を確認します。これはブラウザ権限で回答部分を物理的に遮断する仕組みではなく、ソースコードとテストで監査する実装上の制約です。

独自サーバーへの通信、利用状況の外部収集、外部コードの実行はありません。ただし、実際に送信した指示は通常の利用としてChatGPT側へ送られ、各アカウントの料金・制限・利用規約が適用されます。詳しくは[プライバシー](../../PRIVACY.md)と[セキュリティ](../../SECURITY.md)を参照してください。

ChatGPT側の画面仕様の変更などにより状態を確認できず、安全のため停止する場合があります。自動テストと実サービスでの確認を区別した[検証の説明](../verification/README.md)と、[実ブラウザの確認項目](../release/PC_RELEASE_CHECKLIST.md)もあわせて参照してください。
