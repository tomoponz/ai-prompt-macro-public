# よくある質問

## ChatGPTの回答内容を読み取っていますか？

読み取りません。回答本文の取得・保存・解析・書き出しや、回答内容による条件分岐は行いません（Output-Blind）。

これはブラウザの権限で回答部分へのアクセスを物理的に遮断する仕組みではなく、ソースとテストで監査する実装上の制約です。詳しくは[Privacy](../../PRIVACY.md)を参照してください。

## 「前の回答を改善して」と送れるのはなぜですか？

同じ会話へ、事前に書いた次の指示を送れるためです。以前の回答を文脈として利用するのはChatGPT側です。拡張が回答を指示へ埋め込むわけではなく、文脈の保持範囲も確認・保証しません。

## 最初に何を設定し、どこから開始しますか？

サイドパネルで **「操作するChatGPTタブ」** を選びます。同じ指示を繰り返すなら **「クイック」** を押し、指示・回数・待機時間を設定します。

複数の指示は **「手順を貼り付け」** にAIPM Flowを入力します。必要なら、その中の **「AIに手順を作ってもらう」** から作成ガイドをコピーしてください。対象と実行前プレビューを確認し、**「この内容で自動送信を開始（N回）」** を押します。確認した内容は開始時に保存・照合されるため、手動保存やタブID転記は不要です。詳しくは[はじめて使う](../getting-started/README.md)に沿って操作できます。

送信せず入力欄に置くDraft、部分実行、ライブラリなどの詳細編集は **「ワークスペース」** → **「Flow / ワークフロー編集」** で行います。

## ワークフローとFlowは同じものですか？

作り方と保存形式が異なります。**ワークフローエディター**では画面上で手順を組み立て、**Flowエディター**ではAIPM Flowというテキスト形式で記述します。Flowも検証後に実行用の手順へ変換されます。内部形式を知る必要はありませんが、使用したエディターと **「保存済み実行内容」** の種類を確認してください。

## ワークスペースから実行できますか？

開始・一時停止・再開・停止はサイドパネルで行います。ワークスペースは編集・保存と保存済み記録の閲覧用です。編集対象のタブIDを変えても、サイドパネルの操作対象は変わりません。

## 同じ指示が二重送信されることはありますか？

重複送信を防ぐため、各自動送信では事前に送信処理の記録を保存し、安全確認後に送信ボタンを1回だけ操作します。送信結果が不明な場合は、同じ指示を自動再送せず停止します。

ただし、利用者が手動で同じ指示を送ったり、送信済みの指示を新しい実行へ含めたりすることまで防ぐものではありません。結果が不明なときはChatGPT側を確認して **「停止」** し、必要なら未送信の指示だけで新しく開始してください。

## 送信確認済みなのに、なぜ止まりますか？

送信確認と、生成完了・次の入力準備の確認は別です。**「送信は確認済みですが、生成完了を確認できないため停止しました。同じ指示は自動再送しません。」** と表示された場合、送信済みという確定は維持されています。

ChatGPT側で生成状態を確認して **「停止」** してください。「送信できなかった」と解釈して同じ指示を再送しないでください。

## 会話タイトルや「表示中」で送信先が変わりますか？

変わりません。「操作対象」が送信先です。「表示中」はこのウィンドウで表示しているタブを示すだけです。手動の表示名、ページタイトル、未取得時の表示の順で識別し、同名の会話は実際のタブと「詳細」のIDを確認してください。

ChatGPTタブのページタイトルは、サイドパネルで見分けるための一時表示にだけ使います。タイトルから送信先や会話の同一性を判断せず、Run・送信記録・診断情報や永続ストレージへ保存しません。開発者へ送信することもありません。ChatGPTの回答本文を読まないOutput-Blindの方針は維持しています。

## 新しい会話で最初の指示の後に止まるのは不具合ですか？

安全のための確認です。最初の送信ボタン操作後、会話のURLが変わっただけでは、正しい対象会話だと判断して自動継続しません。

同じタブで、その操作で作られた会話と最初の指示が1回だけ送られたことを確認し、**「再開」** を一度押します。拡張が対象を再確認できれば、その指示を既送信の1回として数えて残りへ進みます。最初の指示は再送しません。別会話へ移動した場合や確信がない場合は **「停止」** してください。

## 止まったらどうすればいいですか？ 「再開」が使えないのはなぜですか？

サイドパネルの **「理由」「次の操作」** を先に確認してください。「一時停止中」「確認が必要」「安全のため停止」は異なる状態です。

利用者による一時停止、確認ポイント、入力だけして確認、指定時刻の遅れ、新しい会話の確認など、許可された状態だけ再開できます。送信結果不明、対象会話・ページの確認失敗、同じ会話の同時操作の競合などは通常の再開ができません。**「開始」「再開」** を連打せず、ChatGPT側を確認して **「停止」** してください。

CAPTCHA・ログイン・利用上限・サービスエラーは拡張で回避しません。ChatGPT側で正規に対処し、表示に従ってください。

## 「入力だけして確認」と「確認ポイント」の違いは？

- **入力だけして確認**: 安全に書き込める空の入力欄へ指示を置き、自動送信せず **「確認が必要」** で止まります。既存の下書きや添付があれば書き換えません。
- **確認ポイント**: 入力欄へ書かず、設定した確認メッセージを表示して止まります。

どちらも、内容を確認して次へ進めてよい場合だけ **「再開」** します。指示を手動送信した場合は、必要な生成が終わったことも自分で確認してください。

## 「停止」はChatGPTの回答生成も止めますか？

止めません。AI Prompt Macroの今後の自動操作を止めます。生成そのものを止めたい場合は、ChatGPT側の停止ボタンを自分で操作してください。

## ChatGPTのタブを切り替えてもいいですか？

ブラウザで別のタブを見ることと、サイドパネルの操作対象を変えることは別です。自動化は開始時のタブに結び付いています。サイドパネルの開始・一時停止・再開・停止は、その時点で明示選択しているタブだけに作用します。

実行中の対象タブでは、別の会話への移動や入力欄・添付の手動編集を避けてください。表示名・識別色・グループは見分けるためだけの情報です。同じ会話を複数のタブから同時に操作しようとすると、安全機構が競合を止めます。

## PCを閉じたり、ブラウザを終了したりしても実行されますか？

PCがスリープ・休止・電源オフになると進みません。Chrome / Edgeを完全に終了して再起動しても、以前の実行は自動継続せず、指定時刻の予定とスリープ防止は解除されます。ChatGPT側の送信状態を確認し、必要な残りだけを新しく設定してください。

ノートPCの蓋を閉じたときの動作はOS・機器設定によります。スリープする設定なら進みません。起動状態で使う場合は発熱と通気にも注意してください。

## スリープ防止は何をしますか？ 画面を消しても動きますか？

サイドパネルの **「スリープ防止」** は、実行中だけPC本体の自動スリープを抑えるよう要求します。画面の消灯は許可します。一時停止・停止・完了でその実行の要求を解除し、有効な実行が複数あれば最後の1つが止まるまで維持します。

すでにスリープ中のPCを起こす機能ではありません。手動スリープ、蓋を閉じる操作、OS・組織の設定を必ず上書きする保証もありません。

## 指定時刻にPCやブラウザを起動できますか？

できません。**「指定時刻まで待つ」** は、同じブラウザ起動中に待機する機能です。同じ起動中にスリープから戻って時刻を過ぎていた場合は、設定した **「遅れたとき」** の対応を使います。

## ページを再読み込みすると続きますか？ 拡張の再読み込みとは違いますか？

ChatGPTページの再読み込み（Ctrl+R）では、同じブラウザ起動中・同じタブ・同じ会話で、安全を確認できる状態だけ復旧できます。送信確認済みの生成待ちや保存済みの待機は続けられる場合がありますが、確認前に中断した通常送信は不明として止まり、自動再送しません。新しい会話の確認待ちも自動解除しません。

**「拡張を再読み込み」** は開発版の更新用です。サイドパネルからは、全タブに実行中・一時停止中の自動化がないことを確認できる場合だけ許可します。状態不明・不正な応答・確認失敗では拒否し、確認中の重複操作は無視します。拡張管理画面からの操作にはこの確認は適用されないため、更新前にすべての自動化を停止してください。拡張の更新後はChatGPTページも再読み込みします。

ブラウザ内部でバックグラウンド処理が再生成されることも、ブラウザ全体の終了・再起動とは異なります。詳しくは[ユーザーガイド](../user-guide/README.md)の「再読み込みと再起動」を参照してください。

## タブを閉じたら、編集内容や実行はどうなりますか？

そのタブの実行は続行不可となり、指定時刻の予定とタブ別の編集内容を削除します。ブラウザの完全再起動では、タブ別編集内容と選択対象も消去します。別のページでタブIDが再利用されたときに、古い実行を誤って結び付けないためです。

繰り返し使いたいAIPM Flowは、ワークスペースの **「Flowライブラリ」** へ明示保存するか、テキストファイルへ書き出してください。ライブラリはタブ別編集状態とは別にローカル保存されます。保存・読み込みだけでは実行しません。

## 50回以上送れますか？

1回の実行の自動送信は最大50回です。無限繰り返しはありません。画面の設定だけでなく、実行時にも上限を確認します。

`MAX_SENDS_PER_RUN = 50`を実行時にも検証します。明示された`maxSends`や送信手順の`repeat`が非数値、`NaN`、`Infinity`、空文字、`null`、オブジェクト、0以下、小数、50超なら、実行作成や送信ボタン操作の前に拒否します。省略時だけ`maxSends`は再計算した送信予定数（最低1）、`repeat`は1になります。

手順全体の送信予定数が`maxSends`または50を超える場合も拒否します。保存状態が途中で不正になった場合は`send_budget_invalid`として再開不可で停止し、送信しません。ちょうど50回は有効です。

## 回答内容で手順を分岐できますか？

できません。「回答に『完成』があれば終了」「点数が80未満なら繰り返す」「回答内のURLを次の指示へ渡す」といった動作は、回答本文を読まない設計の対象外です。

## APIキーやChatGPT Plusは必要ですか？

APIキーは不要で、OpenAI APIは呼び出しません。拡張にPlus必須の判定はありませんが、ログインしたアカウントで通常の指示を送れる必要があります。利用可能なモデル・料金・利用上限・規約はChatGPT側に従います。「APIを使わない」は「ChatGPTが無料・無制限」という意味ではありません。

## ClaudeやGeminiでも自動実行できますか？

できません。自動操作対象はPC版ChatGPT Webだけです。ワークスペースの **「ヘルプ・AIヘルパー」** は説明文をコピーする補助機能です。その文章を別のAIへ手動で貼り付けてFlow案を作ってもらうことはできますが、自動連携やAPI連携はしません。

## データは外部へ送られますか？

拡張の設定・指示・手順などはローカル保存します。独自サーバー、利用状況の外部収集、外部コードの実行はなく、診断記録には指示や回答本文を保存しません。ただし、実際に送信した指示は通常のChatGPT利用としてChatGPT側へ送られます。

## ChatGPTの画面が変わると止まることがありますか？

あります。入力欄、送信ボタン、生成状態などを一意に確認できない場合は、推測して操作せず停止します。自動テストやブラウザfixtureの成功は、現在の実ChatGPTへの対応証明ではありません。リリース前には[PC Release Checklist](../release/PC_RELEASE_CHECKLIST.md)に沿った実Chrome / Edgeでの確認が必要です。
