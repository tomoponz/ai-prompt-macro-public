# 現行の貼り付けテキストカードへの対応（ローカル r2）

統合版の識別名: `0.4.3 r2`。以下のローカル再現・検証記録は、先行候補 `0.4.2 local 2026-10-28 r2` に対するものです。統合版では技術バージョンを上げ、旧content scriptを既存のバージョン不一致ガードで区別します。

## 観測と修正前の再現

2026-10-28 に利用者から提供された form の HTML では、貼り付けテキストのカードは `data-composer-attachments` 領域内の `span.composer-attachment-surface.group/resource-card` でした。削除ボタンのラベルは「貼り付けたテキストの添付を削除」。旧形式の `data-testid`、`role="group"`、`group/file-tile` はありません。カードから form までの祖先は11段です。

匿名化した観測 fixture と r1 の本番検出コードを隔離ブラウザで実行し、実タイル1個に対して `known:true / count:0 / inspectedCandidates:0 / fileTileFallbackSeen:false` となる失敗を記録しました。入力欄は空で送信ボタンは有効でした。r1 の既存試験合格は、この新しい構造への対応を実証していません。

これは候補の重複除外やボタン数判定より前の検出漏れです。また、セレクタだけ追加しても、旧カードの署名に使う form までの深さ上限8段に届かない別の障害が残ります。待ち時間を延ばす対応では解消しません。

## 変更

- 現行カードを同じ form・composer body・添付領域の中で認識します。カード→添付領域と添付領域→body をそれぞれ最大4段で検証し、旧方式の深さ上限は広げていません。
- 既存・残留・非表示カード、未知の要素を含む添付領域、別 body のカード、曖昧な削除操作は送信前に拒否します。同じ form 内で、選択された composer surface の外側に残るカードも「添付なし」にはしません。別 form やページ本文のカードは現在の入力に含めません。
- 旧形式のカードも既存の判定を維持し、新しい添付領域に配置されたときの互換性を確認します。
- プレビュー用 overlay ボタンは構造で識別します。本文由来のラベルが「Remove file…」や削除ボタンと同じ文言でも、削除操作の証拠にはしません。実際の削除操作が欠ける場合は停止します。
- 入力 transaction・手操作検知・Pause・キャンセル・回数管理・既存入力の追記方式は r1 から変更していません。通常文字とウェブ検索 pill の保持、最初の1回だけの共送信、再開時の二重追記防止を回帰試験します。

追加した現行カード認識は、今回観測された日本語の削除ラベルを対象とします。別言語や未知のカード構造まで対応済みとは扱いません。

## 確認の境界

観測 fixture は、個人のID・プレビュー文・装飾SVGを置き換え、判定に関係する要素・属性・祖先階層を保持しています。隔離ブラウザの送信はローカルの合成イベントです。ChatGPT のイベント処理、実際のファイル本文、実アカウントへの送信を試験したものではありません。

観測時は home 画面でした。新規チャットでは手動の初回送信で会話を確定する現行制約を変更していません。fixture の自動送信検証は仮の会話URL上で実行し、添付検出と新規チャットの開始制約を分けます。

限定条件付きの添付送信は、空の添付状態から始まる同じ入力操作、同じ対象、単一の候補、手操作の不在などの履歴を利用します。構造を検出できても、添付本文とプロンプトの完全一致を証明するものではありません。同じ期間に現れる、構造上区別できない別処理の添付という既知の残余リスクは解消したと扱いません。
