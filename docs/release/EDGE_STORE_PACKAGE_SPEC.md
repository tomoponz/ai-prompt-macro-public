# Microsoft Edge Add-ons パッケージ仕様

状態: パッケージの仕様のみを定めます。実際のパッケージは、最終監査とライブ受け入れ確認（live acceptance）を通過した候補commitから生成します。

## 目的

Microsoft Edge Add-onsに必要な最小限の、決定的（deterministic）なZIPを作成します。このZIPは、知人向けの手動配布用ZIPとも、GitHubリポジトリのアーカイブとも別に扱います。

## パッケージのルートに含めるもの

最低限、次を含めます。

```text
manifest.json
_locales/**
src/**
```

また、`manifest.json`、HTML、CSS、同梱するJavaScriptから実際に参照されるローカルの画像・フォント・静的ファイルも含めます。

リポジトリに存在するという理由だけで、ファイルを含めてはいけません。

## 除外するもの

```text
.git/**
.github/**
node_modules/**
tests/**
evals/**
docs/**
research/**
トレースファイル（trace files）
Partner Centerの掲載用にだけ使うスクリーンショット
ローカルのブラウザプロファイル
カバレッジの出力
開発者向けのメモ
非公開の監査用作業ファイル
認証情報・秘密情報（credentials/secrets）
```

Store掲載用のロゴ、スクリーンショット、プロモーション用タイルは、現在のStore UIが明示的に別の方法を求めない限り、Partner Centerで別途アップロードします。

## 決定的なリリース記録

Storeパッケージの記録ごとに、次の項目を記入します。項目名は記録テンプレートとしてそのまま使います。

```text
Package filename:
Source commit SHA:
Manifest version:
Included paths:
Excluded paths:
SHA-256:
Generated at:
Generated by:
```

| 項目 | 記入する内容 |
| --- | --- |
| `Package filename` | パッケージのファイル名 |
| `Source commit SHA` | パッケージの生成元commitのSHA |
| `Manifest version` | `manifest.json`の拡張機能バージョン |
| `Included paths` | 含めたパス |
| `Excluded paths` | 除外したパス |
| `SHA-256` | パッケージのSHA-256ハッシュ |
| `Generated at` | 生成日時 |
| `Generated by` | 生成者 |

## 生成ルール

未コミットの変更が残った作業ツリー（dirty working tree）からは、決してパッケージを作成しません。

必須の順序:

```text
exact audited commit
  -> clean tree
  -> automated checks
  -> live Edge acceptance
  -> package from exact commit
  -> inspect ZIP contents
  -> SHA-256
  -> upload to Partner Center
```

1. 監査済みの正確なcommitを使う（exact audited commit）
2. 作業ツリーがクリーンであることを確認する（clean tree）
3. 自動チェックを実行する（automated checks）
4. 実際のEdgeで受け入れ確認を行う（live Edge acceptance）
5. その正確なcommitからパッケージを生成する（package from exact commit）
6. ZIPの内容を検査する（inspect ZIP contents）
7. SHA-256ハッシュを算出する（SHA-256）
8. Partner Centerへアップロードする（upload to Partner Center）

ライブ受け入れ確認の後にソースファイルまたはmanifestファイルが1つでも変わった場合は、そのZIPを破棄し、新しいcommitに対して必要なゲートをやり直します。

## 生成後の検査

アップロード前に、次を確認します。

- `manifest.json`がZIPのルートにある
- manifest・content script・service worker・サイドパネルから参照されるすべてのファイルが存在する
- パッケージ内のファイルに、ローカルの絶対パスが含まれていない
- 秘密情報・トークン・非公開のアカウント情報が含まれていない
- 意図的に必要な場合を除き、`.map`やデバッグ用の生成物が含まれていない
- manifestの権限が、監査済みの候補と完全に一致している
- リリース手順で展開済みパッケージのスモークテストが必要な場合は、パッケージを新しいフォルダーへ展開し、Edgeで一度手動で読み込む

## バージョン

manifestに記載された、有効な数値形式の拡張機能バージョンを使います。`-beta.1`のようなファイル名の接尾辞を、ブラウザが扱うバージョンの根拠にしてはいけません。

最初の非公開（Hidden）Storeリリースでは、バージョン変更が必要な場合を除き、受け入れ済みのmanifestバージョンをそのまま維持します。manifestのバージョンを変更した場合は候補の変更として扱い、必要なチェックをやり直します。
