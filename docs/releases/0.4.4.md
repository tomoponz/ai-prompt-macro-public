# 0.4.4 — 実行状態の保護とサイドパネルの改善

## 変更点

- ページ内の別フレームからの復旧要求が、操作対象のRunを取得して誤停止させる経路を拒否します。
- 古い文書からの遅れた停止要求が、同じRun IDで再接続・更新された実行へ作用しないようにします。停止対象のリビジョン・セッション・会話・文書と要求元を照合し、短時間だけ有効な一回限りの停止権限を使います。対象と元の状態を確認できる現行文書の復旧停止は維持します。
- 送信確認後の進捗表示を整合させ、狭いサイドパネルで長い停止理由・進捗・操作ボタンがはみ出す表示を修正します。
- 拡張アイコンを白背景・黒いピクセル文字の「APM」に更新します。

送信確認済みの指示や、送信結果が不明な指示を自動再送する変更はありません。既存入力への追記、条件付きの長文添付送信、新規チャットでの手動初回送信という従来の動作は維持します。権限や対応ホストを増やさず、ChatGPTの回答本文を取得しないOutput-Blindの方針も維持します。

## 既知の制限と検証範囲

- 停止要求元が保存された文書と異なり、現在のページも確認できない場合、古い文書か正当な新しい文書かを判別できません。他の実行を止めないよう保存状態を変更しないため、ページ側で進行を止めてもRunの保存表示が「実行中」のまま残る場合があります。停止権限が期限切れになり、同じ状態の確認で更新できなかった場合も同様です。保存Runが実行中ならスリープ防止の要求も残り得ます。同じセッション・タブ・会話へ再読み込みや「戻る」で復帰すると、安全条件を満たす残りの処理が自動再開する場合があります。診断と送信済みの範囲を確認し、再読み込みの前に対象Runを明示的に「停止」してください。
- 正当な送信元・元の状態による停止と、古い状態・別文書・別タブ・再起動後の要求による変更拒否をローカル回帰試験で検証しています。単体試験や模擬DOMの成功は、実ChatGPTでの成功を意味しません。公開コミットの自動試験結果は、そのコミットのGitHub Actionsを確認してください。
- 過去の版について、利用者から短文20回の連続送信、長文が添付になった場合の送信成功が報告されています。一方、長文の反復中に停止した報告もあります。今回の変更を適用した実サービスでの連続送信・配布対象Chrome / Edgeでの受け入れ確認は未実施です。
- 長文添付は、同じ入力操作・対象・単一の認識可能な候補・手操作の不在などに基づく条件付き対応です。添付全文とプロンプトの一致を証明する仕組みではなく、未知のUIや構造上区別できない別処理の添付まで対応済みとはしません。[既存の添付対応の検証範囲](../history/resource-card-r2.md)も参照してください。

## 既存の手動導入版を更新する

1. 必要な停止理由・診断、ChatGPTの下書き、APMの未保存の指示・Flow入力を手元へ保存します。
2. 対象を確認して、全タブのRunを「停止」します。更新中の継続や、更新による自動再開を前提にしないでください。
3. 現在の拡張の読み込み元フォルダーを退避します。同じ場所へ0.4.4のファイル一式を配置します。ビルドや`npm install`は不要です。
4. `chrome://extensions`または`edge://extensions`で既存のAPMを再読み込みし、バージョンが`0.4.4`であることを確認します。
5. 下書きを保全済みであることを確認して、開いているChatGPTタブも再読み込みします。旧content scriptが残っていると新しいバックグラウンド処理とのバージョン不一致で拒否されるため、拡張だけの再読み込みでは更新が完了しません。
6. サイドパネルで操作対象と接続状態を確認し、必要な未送信分だけを設定します。確認済みの送信を最初から繰り返さないでください。

別フォルダーの新規読み込みは別の拡張IDになる場合があります。設定や未保存入力が自動で引き継がれるとは限らないため、既存の拡張を先に削除しないでください。旧版へ戻す場合もRunを停止して下書き等を保全し、退避したファイルを元の読み込み場所へ戻した後、拡張とChatGPTタブを再読み込みします。以前の実行を自動継続するための手順ではありません。
